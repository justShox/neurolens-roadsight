# NeuroLens — план на 5 дней (WIUT Hackathon 2026, CV Track)

## 0. Как считается балл и что из этого следует

`Итог = 0.6·M + 0.25·Сайт + 0.15·Код`, `M = 0.7·Score_A + 0.3·Score_B`.

- **Сайт + код = 40% итога** — самые гарантированные баллы. Демо (30% сайта) и «запуск с первой попытки» (40% кода) — приоритет.
  Если пакет не запустился после одной попытки починить окружение, M = 0.
- **Score_A = macro F1 по классам из (GT ∪ наши предсказания).** Предсказанный класс, которого нет в тесте, добавляет ноль в среднее.
  Выводим только классы, прошедшие dev-проверку (белый список в `src/config.py`).
- **Матчинг по tIoU 0.3/0.5/0.7** — постобработка границ сегментов так же важна, как детекция.
- **Лимит 3× длительности видео на Part A + Part B.** Part B получает каждый кадр и не может использовать Part A → детекция гоняется дважды. Цель ≤ 1×.
- `camera.md` **нет** → геометрию сцены (полосы, направления, стоп-линии, переходы, светофор) выводим сами из видео
  (траектории + ручная разметка полигонов на кадре). Параллельно спросить `camera.md` в канале хакатона.

## 1. Архитектура

```
Part A (офлайн)
  decode (шаг 3–5 кадров) → YOLOv8s/11s (FP16) → ByteTrack → сглаживание треков
  → scene layer (полигоны/линии/направления, захардкожены в src/scene.py)
  → детекторы событий (правила по классу) → кандидаты accident/near_miss/fire_smoke → классификатор
  → постобработка сегментов → [[start, end, label], ...]

Part B (каузально)
  step(): детекция+трек каждый 3–5 кадр, иначе last_score
  → признаки (min TTC, торможение, аномальные траектории, пешеход на дороге)
  → логистическая калибровка → EMA + гистерезис → risk ∈ [0, 1]
```

Обучаемое: детектор (COCO-предобучен), детектор огня/дыма, (опционально) классификатор аварий. Остальное — правила.

## 2. Классы и приоритеты

**Tier 1 (обязательно, правила):**

| Класс | Правило |
|---|---|
| stopped_vehicle | скорость < ε ≥ 10 с, на проезжей части, не в очереди у стоп-линии |
| congestion | средняя скорость всех треков направления < порога и высокая загрузка ≥ N с, гистерезис |
| wrong_way | cos(вектор трека, направление полосы) < −0.5 ≥ 1 с |
| jaywalking | нижний центр bbox пешехода в полигоне дороги, вне перехода |
| failure_to_yield | машина в полигоне перехода, пока там пешеход |
| red_light | статус светофора (HSV по ROI лампы или по потокам) + фронт bbox пересекает стоп-линию |

**Tier 2 (если геометрия позволяет):** solid_line_crossing, illegal_u_turn, illegal_turn, stop_line.

**Tier 3 (обучаемое):** accident (кандидаты по правилам: одновременное торможение, пересечение bbox, слипание треков → остановка;
верификация классификатором или open-VLM, если влезает во время), near_miss (TTC < 1 с + резкий манёвр, высокий порог),
fire_smoke (YOLO на D-Fire + устойчивость ≥ 2 с). road_obstacle — только если dev-проверка чистая.

## 3. Постобработка сегментов

- медианное сглаживание флагов → сегменты;
- склейка дырок < 1–2 с, удаление блипов < 0.5–1 с (по классу);
- одновременные события одного класса → один сегмент;
- систематический сдвиг границ под конвенции (подбирается на dev);
- `end ≤ duration`; тюним по F1@0.7.

## 4. Part B

- min TTC между парами треков (экстраполяция центров/bbox на 0–5 с), торможение, аномалии;
- `risk = sigmoid(a/TTC + b·decel + ...)`, 0.5 ≈ «авария в ближайшие 5 с»; калибровка на CCD/DoTA;
- EMA и мало тревог (ложные тревоги бьют precision); осмысленное ранжирование и в «спокойных» кадрах (AP).

## 7. План по дням

Роли: **ML-1** — детекция, треки, правила; **ML-2** — аварии, огонь, Part B, разметка; **WEB** — репо, сайт, демо.

### День 1 — фундамент
- Все: скачать 4 видео в `samples/`, посмотреть их целиком, записать, что происходит.
- ML-1: EDA (fps, разрешение, длительность, свет), YOLO+ByteTrack на всех сэмплах, heatmap движения, треки → направления полос.
  Разметить полигоны (дорога, полосы, стоп-линии, переходы, ROI светофора) → `src/scene.py`. Замер скорости на Colab T4.
- ML-2: разметка dev-сета (`labels/dev_labels.json`) по конвенциям задания; скачать CCD/DoTA-подвыборку и D-Fire.
- WEB: скелет репо, `solution.py` → `src/`, скрипт «чистый venv → run → validate», каркас сайта (Next.js на Vercel) + HF Space.
- **Итог дня:** треки есть, сцена описана, dev-разметка готова, валидный `predictions.json` (пусть пустой).

### День 2 — базовая версия Part A
- ML-1: `segments.py` + stopped_vehicle, congestion, wrong_way, jaywalking, failure_to_yield. Первый прогон `evaluate.py --gt`.
- ML-2: кандидаты accident/near_miss на правилах; Part B v0 (TTC); начать обучение fire_smoke на Colab.
- WEB: `viz.py` — рендер размеченных видео (bbox, id, события), таймлайн; страница EDA с графиками.
- **Итог:** первая цифра Score A на dev.

### День 3 — расширение
- ML-1: red_light / stop_line (статус светофора), solid_line_crossing, развороты/повороты.
- ML-2: fire_smoke в пайплайн; верификатор аварий (классификатор клипов или VLM, если по времени); калибровка риска.
- WEB: бэкенд демо (Gradio/FastAPI на HF Space, CPU, YOLO nano, шаг 5): загрузка ≤ 2 мин, прогресс, таймлайн, видео, кривая риска.
- **Итог:** все целевые классы в пайплайне, демо работает end-to-end.

### День 4 — тюнинг и измерения
- ML-1: подбор порогов по F1@0.7 на dev; решение, какие классы оставить в белом списке.
- ML-2: абляции (детектор s vs m, шаг 3 vs 5, с/без трекинга) — цифры на сайт; тюнинг тревог Part B; замер времени на T4.
- WEB: страница результатов (все 4 видео размечены, таймлайны по клику, кривые риска, ошибки), дашборд, мобильная версия.
- **Итог:** финальная модель-кандидат, время ≤ 1× длительности.

### День 5 — заморозка и сдача
- До обеда: заморозка кода. Чистый запуск на свежем Colab: `pip install -r requirements.txt` →
  `python run_submission.py --videos samples --out predictions_samples.json` → `evaluate.py --validate-only`;
  двойной прогон на детерминизм.
- README: установка, веса, подход, что обучено / что правила, датасеты и лицензии, сиды, кто что делал.
- Сайт: отчёт (что сработало / что нет / что дальше), команда и портфолио, ссылки; стресс-тест демо; пинг против засыпания Space.
- Тег коммита заранее, не в последний час.

## 8. Риски

- **Нет camera.md** → сцену выводим сами; спросить в канале в день 1.
- **Светофор не виден** → red_light/stop_line косвенно по потокам или не выводим.
- **FP редких классов** → белый список, выводим только проверенное.
- **Время** → замер на T4 в день 1 и 4, запас ≥ 2×.
- **Демо падает/засыпает** → обработка ошибок, лимит размера, пинг.
